# 처리 시간 측정 인수인계 (논문 VI장 표용)

이 문서만 읽어도 맥락을 알 수 있게 썼다. 원자료는 같은 폴더의 `raw.csv`, 전체 표는 `table.md`.

## 1. 무엇을 쟀나
Empty My Room 파이프라인(SAM2 → LaMa → SD ControlNet → 가구 추출 → uLayout → SAM3D/Omni3D)의 서버 처리 시간.
장면 4개, 장면당 워밍업 1회(집계 제외) + 측정 5회, 회차마다 순차(sequential)와 병렬(parallel) 각 1번.
사용자 클릭 시간은 제외(클릭 좌표를 입력으로 줌). 측정일 2026-10-14. 기존 파이프라인 코드와 임계값은 수정하지 않음.

## 2. 측정 환경
- **로컬 개발 PC에서 측정했다(AWS 아님).** WSL2: Linux 6.6.87.2-microsoft-standard-WSL2, glibc 2.39
- GPU: NVIDIA GeForce RTX 4090, 24,564 MiB, 드라이버 595.95 (nvidia-smi 헤더의 `CUDA Version: 13.2`는 드라이버 지원 상한이며 실제 런타임 아님)
- 측정 시작 시 GPU 사용량 2,488 MiB(uLayout·Omni3D 사이드카 상주분). 측정 중 :8001 백엔드는 내려둠. 측정 후 복구함.

| 프로세스 | env | Python | PyTorch | CUDA(빌드) | cuDNN |
|---|---|---|---|---|---|
| 측정 스크립트 (SAM2, LaMa, SD, SAM3D 직접 import) | sam3d | 3.11.15 | 2.5.1+cu121 | 12.1 | 9.19.00 |
| uLayout 사이드카 :8002 (HTTP) | uLayout | 3.10.20 | 2.2.0+cu121 | 12.1 | 8.9.02 |
| Omni3D 사이드카 :8003 (HTTP) | omni3d | 3.10.20 | 2.2.0+cu121 | 12.1 | 8.9.02 |

논문 V장의 "CUDA 12.1 / PyTorch 2.5.1 / Python 3.11"은 **메인 파이프라인(sam3d env)에만 해당**한다. 사이드카는 PyTorch 2.2.0, Python 3.10.

## 3. 방식
- `time.perf_counter()`, GPU 단계는 전후 `torch.cuda.synchronize()`.
- 직접 import: SAM2, LaMa, SD, SAM3D. HTTP: uLayout, Omni3D(왕복 시간).
- **전체(e2e)** 는 단계 합이 아니라 따로 잰 wall-clock. SD 로드/해제 포함, SAM2/LaMa 세션 시작 재로드 제외.
- SD는 요청마다 로드/해제(inpaint.py 구현). 로드는 `SD 로드` 열로 분리. SAM3D 파이프라인은 상주(로드 32.53초, 프로세스당 1회).
- 병렬 구간: uLayout `/infer`‖`/rectify`, 가구별 SAM3D‖Omni3D (프런트가 실제 동시 전송하는 곳).
- **스케일 계산** = Omni3D `/estimate` 왕복. SAM3D pose_scale 환산은 `generate()` 안의 numpy 몇 줄이라 분리 불가, SAM3D 열에 포함. **프런트 JS의 카메라 포즈 기반 광선–바닥 교차는 측정 제외.**
- 프런트가 Omni3D를 부르는 카테고리는 `스탠드 조명, 조명, 액자, 그림, 거울, 커튼`뿐. 침대·소파·의자·협탁은 호출하지 않으므로 스케일 열은 sceneB(스탠드 조명, 액자)만 채워짐.

장면(가구): sceneA(침대, 협탁), sceneB(소파, 스탠드 조명, 액자), sceneC(침대, 의자), sceneD(침대). 클릭 좌표는 `scenes.json`, 마스크 확인용 오버레이는 `masks/`.
사진 원본 파일명은 알 수 없음(첨부 시 소실). 가구 선택은 사용자가 정한 것이 아니라 사진을 보고 정함(사용자 예시 `<예: …>`가 자리표시자였음). sceneA의 펜던트 조명은 SAM2가 조명 2개+화병을 한 마스크로 묶어 협탁으로 교체함.

## 5. 반드시 함께 적어야 하는 주의점
1. **sceneA의 SAM3D 평균은 이상치가 만든 값.** 협탁 166.91초·270.12초, 침대 69.46초 (중앙값 27.72). 이상치는 평균에서 제외하지 않고 그대로 두었다. 중앙값 병기 권장.
2. **실패 1건, 재실행 안 함.** sceneB 2회차 병렬: Omni3D 120초 읽기 타임아웃(같은 구간 SAM3D 315초). 그래서 sceneB 병렬은 n=4.
3. **uLayout 시간은 `/rectify` 실패 경로의 시간.** 48회 전부 `success=false`(sceneA·B·D: 뒷벽 정면 코너 2개 미검출, sceneC: solvePnP 재투영오차 30.3px>10px). rectify 성공 시 시간은 이 표에 없음.
4. **병렬이 순차보다 빠르지 않았다**(sceneB·C는 오히려 느림). 같은 GPU에서 SAM3D와 Omni3D를 겹치면 이득이 없다. 병렬일 때 Omni3D는 약 5초까지 늘어남(순차 0.3초).
5. **이상치의 원인은 확인되지 않았다.** GPU 메모리 경합을 의심했으나 근거가 약하다. 아래 6 참고.
6. **GPU 메모리 peak는 측정하지 못했다.** `run.log`의 값은 실행 종료 직후 스냅샷 52개(최소 14,795 / 중앙 15,825 / 최대 17,047 MiB)로 실행 도중 순간 최대치가 아니다. 별도로 한 번 찍은 21,428 MiB(여유 약 3.1GB, 18:19 sceneB 2회차 병렬 실패 직후)가 로그 최대보다 4.4GB 높으므로 실제 peak는 더 높다. "GPU 여유 약 3GB"를 측정 전반의 값으로 쓰면 안 된다. 이상치와 GPU 경합의 연관은 가설이다. 확인하려면 nvidia-smi 주기 로거를 붙여 재측정해야 한다.
7. 로컬 RTX 4090 결과이며 배포(AWS g5/g6) 환경과 다르다. 캡션에 환경을 명시할 것.
