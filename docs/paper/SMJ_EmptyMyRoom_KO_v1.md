# TITLE
단일 실내 사진 기반 SAM3D 가구 복원과 인터랙티브 3D 인테리어 재구성 시스템

# TITLE-EN
An Interactive 3D Interior Redesign System with SAM3D-based Furniture Reconstruction from a Single Indoor Image

# AUTHORS
심우현, 위영림, 손예진, 김성기

# AUTHORS-EN
Woo-hyun Sim, Young-rim Wee, Ye-jin Son, Seong-Ki Kim

# ABSTRACT
상용 인테리어 시뮬레이터는 자사가 구축한 3D 카탈로그에 등록된 가구만 배치할 수 있어, 사용자가 이미 보유한 가구를 옮겨 보는 용도로는 사용할 수 없다. 본 논문은 방 사진 한 장만으로 이 제약을 제거하는 end-to-end 웹 시스템을 제안한다. 사용자가 가구를 클릭하면 SAM2가 인스턴스 마스크를 생성하고, LaMa와 Canny 엣지로 조건화한 Stable Diffusion ControlNet이 2단계로 가구를 제거해 빈 방을 복원한다. 동일한 마스크가 SAM 3D Objects로 입력되어 가려진 면까지 채워진 컬러 메쉬가 되고, uLayout이 추정한 방 치수와 카메라 포즈 위에 구성한 Three.js 공간에 배치된다. 본 시스템에서 가장 핵심적인 문제는 생성된 메쉬가 정규화 좌표계에 있어 미터 단위 크기를 알 수 없다는 점이었다. 이를 위해 카메라 포즈 기반 광선–바닥평면 교차, Cube R-CNN의 oracle 2D 주입, SAM3D 포즈 디코더의 스케일 값, 방 크기 비례로 구성된 4단계 폴백 체인을 설계하였다. 줄자 실측과 비교한 결과, 가구 전체가 화면에 들어오고 하단이 바닥에 닿아 보이는 조건에서 카메라 포즈 기반 추정의 오차는 0.3~5.4 %였다. 반면 클로즈업 구도에서는 54 % 과대추정, 가구 하단부가 가려진 경우에는 37~43 % 과소추정이 나타났으며, 이때 시스템은 오류를 스스로 검출하지 못한 채 잘못된 크기를 그대로 출력하였다. 또한 서로 다른 프레임워크 세대를 요구하는 모델들을 사이드카 프로세스로 분리해 단일 GPU에서 함께 구동하는 과정에서 관측한 자원 경합과 생성 품질 편차 대응을 함께 보고한다.

# BODY

## INTRODUCTION

인테리어를 바꾸고자 할 때 사용자가 실제로 던지는 질문은 "어떤 새 소파를 살까"보다 "저 옷장을 반대편 벽으로 옮기면 어떨까"에 가깝다. 그러나 이 질문에 답하려면 무거운 가구를 직접 옮겨 보아야 하고, 옮긴 뒤 되돌리는 비용이 크기 때문에 일반 사용자가 시도하기 어렵다.

현재 상용 인테리어 시뮬레이터는 이 질문에 답하지 않는다. IKEA Place [1]를 비롯한 증강현실 앱과 온라인 가구 커머스의 3D 배치 도구는 모두 자사가 구축한 3D 카탈로그 위에서 동작한다. 카탈로그에 등록된 신제품은 실제 치수와 재질까지 정확히 배치할 수 있으나, 사용자의 방에 이미 놓여 있는 가구는 그 목록에 존재하지 않는다. 즉 기존 도구는 구매할 물건을 위한 것이지 보유한 물건을 위한 것이 아니다.

이 간극을 메우려면 임의의 가구 사진을 즉시 3D 자산으로 변환할 수 있어야 하며, 그 전제 조건은 최근에야 충족되었다. 프롬프트 기반 분할 모델은 학습하지 않은 가구도 클릭 한 번으로 분리하고, 대규모 인페인팅 모델은 제거된 영역에 벽과 바닥을 복원하며, 3D 생성 모델은 단일 이미지에서 가려진 면까지 포함한 완결된 메쉬를 생성한다. 본 논문은 이 세 갈래를 하나의 웹 파이프라인으로 통합하여, 사진 한 장에서 시작해 사용자가 직접 가구를 배치하는 3D 씬까지 도달하는 시스템을 제안한다.

본 논문의 기여는 다음과 같다. 첫째, ControlNet 조건 맵에서 마스크 내부 엣지를 제거하여 인페인팅 모델이 제거 대상 가구를 재생성하는 문제를 억제하는 2단계 빈 방 복원 파이프라인을 제안한다. 둘째, 객체 단위로 설계된 3D 생성 모델을 실내 다중 객체 환경에 적용하기 위한 카테고리별 다중 시드 선택 기준과 얇은 물체 보정 방법을 제시한다. 셋째, 정규화 좌표계의 메쉬에 미터 단위 크기를 부여하는 4단계 폴백 체인을 설계하고, 각 경로가 성립하는 조건과 깨지는 조건을 실측으로 정량화한다. 넷째, 의존성이 충돌하는 다수의 모델을 단일 GPU에서 구동하기 위한 사이드카 구조와 자원 배분 방법을 보고한다.

## RELATED WORK

### 가구 인식 및 분할

Segment Anything Model(SAM) [2]은 포인트·박스·텍스트 프롬프트로 임의의 객체를 분리하는 범용 분할 모델이며, SAM2 [3]는 Hiera 백본을 도입해 경계 품질과 속도를 개선하면서 이미지와 비디오를 함께 지원한다. 본 시스템이 SAM2를 채택한 이유는 정확도보다 상호작용 모델에 있다. 사용자가 특정 픽셀을 지목하는 방식은 가구 카테고리를 사전 학습할 필요를 제거하므로, 사용자의 방에만 존재하는 비정형 가구에도 그대로 동작한다.

### 이미지 인페인팅

LaMa [4]는 푸리에 컨볼루션을 활용해 넓은 마스크 영역의 구조를 일관되게 복원하지만 결과가 흐릿하다. 잠재 확산 모델 기반 인페인팅 [5]은 질감을 사실적으로 생성하지만, 가구 제거라는 맥락에서는 잔여 그림자와 마스크 경계를 설명하려는 경향 때문에 존재하지 않던 물체를 생성한다. ControlNet [6]은 엣지·깊이 등 구조 신호를 확산 모델의 조건으로 주입해 생성 결과를 구속한다. 본 논문은 여기에 한 단계를 추가한다. 조건 맵에 제거 대상의 윤곽선이 남아 있으면 오히려 그 윤곽을 따라 가구가 재생성되므로, Canny [7] 엣지를 추출한 뒤 마스크 내부 엣지를 제거하고 조건으로 사용한다.

### 단일 이미지 3D 복원

TripoSR [8]은 대규모 3D 데이터로 사전 학습된 트랜스포머로 빠른 복원을 제공하고, Zero123++ [9]는 단일 이미지에서 다시점 이미지를 생성한다. 3D 가우시안 스플래팅 [10]은 높은 시각 품질을 제공하나 표현이 점 기반이어서 충돌 판정을 적용하기 어렵다. 본 연구는 초기 단계에서 이 세 방식을 모두 시험하였으며, 최종적으로 SAM 3D Objects [11]를 채택하였다. SAM3D는 대규모 3D 오브젝트 데이터로 학습한 shape prior를 사용해 가려진 부분을 추정하고, 마스크를 조건으로 직접 입력받으므로 분할 단계와 자연스럽게 연결된다. SAM3D는 내부적으로 단안 기하 추정 모델 MoGe-2 [12]로 포인트맵을 생성하고, 확산 트랜스포머가 생성한 sparse latent를 FlexiCubes [13] 기반 메쉬 추출기로 변환한다.

### 실내 기하와 미터 단위 스케일

uLayout [14]은 원근 영상과 파노라마 영상을 통합해 방 레이아웃 경계를 추정하며, 내부적으로 Perspective Fields [15]로 카메라의 롤·피치·화각을 얻는다. Omni3D의 Cube R-CNN [16]은 단일 영상에서 물체의 3차원 바운딩 박스를 미터 단위로 예측한다. Total3DUnderstanding [17]은 레이아웃·물체 박스·메쉬를 하나의 좌표계에서 결합 추정하고, PlaneRCNN [18]은 평면을 미터 단위 파라미터와 함께 검출한다. 두 연구가 공유하는 문제의식, 즉 기하를 미터 단위에 결속할 근거가 필요하다는 지적은 본 시스템에도 그대로 적용된다. 다만 두 구현체는 각각 구버전 CUDA 환경을 요구하여 현행 GPU에서 구동되지 않았고, 물체 검출과 메쉬 생성 측면에서는 본 시스템이 이미 이후 세대의 모델을 사용하고 있다. 따라서 본 논문은 두 구현체를 도입하는 대신 기존 파이프라인의 모델로 동일한 목적을 달성하는 방법을 취한다.

## PROPOSED METHOD

### 시스템 구성

제안 시스템은 사용자 관점에서 사진 업로드, 가구 선택, 방 만들기, 3D 배치의 네 단계로 구성된다. 내부적으로는 서로 다른 의존성 스택을 요구하는 모델들로 인해 네 개의 프로세스로 분리되어 있다(그림 1).

프론트엔드는 React와 Vite 위에서 Three.js [19]를 직접 제어한다. 메인 백엔드는 FastAPI 단일 서버로 SAM2, LaMa, Stable Diffusion, SAM3D를 라우터별로 포함한다. 나머지 두 모델은 별도 가상환경을 요구하여 동일 프로세스에 포함할 수 없었다. uLayout은 특정 numpy/opencv/torch 조합에 종속되고, Cube R-CNN은 레거시 Detectron2 및 PyTorch3D 스택을 요구한다. 본 시스템은 이 둘을 독립 포트의 상주 HTTP 사이드카로 구성하고 메인 백엔드가 멀티파트 요청으로 호출한다.

사이드카 분리는 의존성 문제의 해결책인 동시에 두 가지 이점을 제공한다. 첫째, 사이드카가 중단되어도 메인 서비스는 동작한다. 두 라우터 모두 연결 실패를 실패 응답으로 변환하며, 프론트엔드는 이를 폴백 경로의 신호로 사용한다. 방 치수 추정이 실패하면 사용자 입력 치수를 사용하고, 실사 텍스처 정합이 실패하면 사진 패치 타일링으로 전환하며, 크기 추정 사이드카가 없으면 다음 순위의 추정 방법으로 이동한다. 둘째, 모델을 요청마다 로드하지 않아 응답 시간이 유지된다.

전체 흐름은 다음과 같다. 사용자가 가구를 클릭하면 SAM2가 라벨별 인스턴스 마스크를 생성한다. 마스크의 합집합은 인페인팅으로, 개별 마스크는 가구 크롭 이미지로 분기한다. 빈 방 이미지에서 색상·텍스처·방 치수·카메라 포즈를 추출해 Three.js 공간을 구성하고, 가구 크롭은 사용자 요청 시 개별적으로 SAM3D에 입력되어 컬러 메쉬로 변환된다. 빈 방 복원과 가구 복원은 상호 독립적이므로 병렬 수행이 가능하다.

### 인스턴스 분할

사용자는 가구 카테고리를 선택한 뒤 영상 위를 클릭한다. 동일 라벨에 지정된 포인트들은 하나의 그룹으로 묶여 SAM2에 함께 전달되며, 가구 하나당 하나의 마스크가 생성된다.

구현에서 고려한 사항은 세 가지이다. 첫째, 연산량이 큰 영상 인코딩은 요청당 한 번만 수행하고 포인트 프롬프트만 반복한다. 가구 개수가 증가해도 처리 시간이 비례하여 증가하지 않는다. 둘째, 클릭마다 서버를 호출하면 연속 입력 시 요청이 누적되므로 300 ms 디바운스를 적용해 마지막 클릭만 전송한다. 셋째, SAM2는 하나의 클릭에 대해 부분과 전체를 포함하는 다수의 마스크를 반환하는데, 본 시스템은 용도에 따라 선택 기준을 다르게 설정하였다. 빈 방 복원용 마스크는 모델이 제공하는 신뢰도가 가장 높은 마스크를, 가구 추출용 마스크는 면적이 가장 큰 마스크를 선택한다. 가구 전체를 3D로 변환해야 하므로 부분이 아닌 전체가 필요하며, 실험 결과 면적 기준이 전체 영역을 더 안정적으로 선택하였다.

마스크 후처리는 목적에 따라 분기한다. 인페인팅용 마스크는 15 px 팽창으로 여유를 두어 생성한다. 가구 일부를 누락하면 해당 영역이 빈 방 영상에 잔존하므로, 본 파이프라인에서는 과분할보다 미분할이 치명적이다. 3D 변환용 마스크는 카테고리별로 다른 커널의 모폴로지 닫힘 연산을 적용한다. 소파·침대·책상과 같은 대형 가구는 마스크 내부에 큰 공백이 발생하기 쉬우므로 25×25 커널로 보정하고, 조명·화분·시계·액자와 같이 얇거나 작은 물체는 동일 커널 적용 시 형상이 훼손되거나 인접 물체와 병합되므로 5×5 커널만 적용한다. 이후 외곽 컨투어를 채우고 3×3 열림 연산과 경계 가우시안 블러로 알파 경계를 정제한다.

좌표계 정합은 별도의 처리가 필요하였다. 스마트폰 영상은 픽셀 자체는 가로 방향이나 EXIF 회전 정보로 세로 표시를 지시하는 경우가 많다. 브라우저는 이를 자동 적용하고 서버 측 영상 처리 라이브러리는 적용하지 않아 클릭 좌표와 마스크 위치가 불일치하였으며, EXIF 회전을 픽셀에 반영하여 해결하였다. 또한 서버는 처리 속도를 위해 긴 변 기준 1024 px로 축소하여 추론하는데, 바운딩 박스를 축소 좌표계 그대로 반환하면 프론트엔드가 원본 해상도 영상을 잘못된 영역에서 크롭한다. 현재는 모든 바운딩 박스를 원본 좌표계로 환산하여 반환한다.

### 2단계 빈 방 복원

가구 마스크의 합집합을 이용한 빈 방 복원은 두 모델을 직렬로 사용한다. LaMa [4]가 벽과 바닥 등 대형 면의 구조를 1차 복원하며, 결과는 구조적으로 안정적이나 흐릿하다. 그 위에 Canny 엣지로 조건화한 Stable Diffusion 인페인팅을 적용하여 질감을 복원한다.

확산 모델을 제약 없이 적용하면 마스크 영역에 존재하지 않던 가구와 구조물이 생성된다. 본 논문은 네 가지 장치를 적용하였다.

* 마스크 내부 엣지 제거. 가장 핵심적인 장치이다. Canny 엣지를 LaMa 결과에서 추출한 뒤, 팽창된 마스크 내부의 엣지를 0으로 제거하고 ControlNet 조건으로 사용한다. 이 과정을 생략하면 제거 대상 가구의 윤곽선이 조건 맵에 잔존하여 ControlNet이 해당 윤곽을 따라 가구를 재생성한다.
* 비대칭 팽창에 의한 그림자 제거. 마스크를 41×41 커널로 두 번 팽창한 뒤, 하단 절반만 유효한 40×40 커널로 세 번 추가 팽창한다. 가구 하단의 그림자까지 마스크에 포함해야 결과가 빈 방으로 인식된다.
* 조건 강도 조정. ControlNet 조건 강도를 0.5로 설정하여 잔존하는 구조선은 유지하되 과도한 추종을 억제한다.
* 네거티브 프롬프트. 가구·침대·의자·테이블 등을 명시적으로 억제한다.

마스크는 조건 맵 생성 이후에 51×51 가우시안 블러로 평활화한다. 블러를 먼저 적용하면 경계가 흐려져 엣지 제거의 임계 판정이 모호해지므로 순서가 중요하다.

**Fig. 2.** 빈 방 복원 파이프라인. (a) 입력 영상, (b) SAM2 마스크 합집합, (c) LaMa 1차 복원, (d) 엣지 제거 없이 ControlNet을 적용한 결과, (e) 마스크 내부 엣지를 제거한 제안 방식.

### 3D 방 공간 구성

빈 방 영상 위에 3D 공간을 구성해야 한다. 본 연구는 먼저 방 전체를 생성 모델로 복원하는 방식을 시도하였다.

SAM3D에 방 내부 마스크를 입력하여 공간 전체를 단일 객체처럼 복원하는 파이프라인을 구현하였다. 마스크 외부는 회색으로 채워 모델이 내부 구조에 집중하도록 하고, 벽 색상은 마스크 상위 50 % 픽셀의 평균으로, 바닥 색상은 영상 하단 15 %의 중앙 80 % 영역 평균으로 산출한 뒤 Y 좌표 하위 20 % 버텍스에만 바닥 색상을 적용하였다. 메쉬 품질을 위해 미세 면적의 퇴화 면을 제거하고 구멍을 메운 뒤 약한 라플라시안 평활화를 적용하였으며, 바닥·뒷벽·좌우벽 네 면의 정규화 거리 0.28 이내 버텍스를 해당 평면으로 최대 90 % 이동시키는 평면 스냅을 추가하였다.

단순한 구조의 방에서는 벽과 바닥이 비교적 정확히 복원되었으나, 가구·창문·문이 많은 공간에서는 바닥 면이 생성되지 않거나 벽면 질감이 왜곡되었다(그림 3). 이는 SAM3D의 shape prior가 볼록한 단일 객체를 전제로 학습된 반면 실내 공간은 오목한 껍질 구조라는 도메인 차이에서 기인한다. 또한 인테리어 시뮬레이터에서 방은 배치와 충돌 계산의 기준 좌표계이므로, 실제 치수를 알 수 없고 표면이 균일하지 않은 메쉬 위에서는 배치 결과를 신뢰할 수 없다. 본 시스템은 이 경로를 서비스에서 제외하고 코드는 API로 유지하였다.

**Fig. 3.** SAM3D를 방 전체에 적용한 결과. 단순한 구조에서는 벽·바닥이 복원되나(좌), 요소가 많은 공간에서는 바닥 면 미생성과 질감 왜곡이 발생한다(우).

대안은 정확한 직육면체를 구성하고 그 표면에 실제 사진을 적용하는 방식이다. 이를 위해서는 방의 미터 단위 치수가 필요하며, 이는 uLayout [14] 사이드카가 제공한다. 사이드카는 Perspective Fields [15]로 영상의 롤·피치·수직 화각을 추정하고, 그 값으로 원근 영상을 512×1024 등장방형 도메인으로 투영한다. uLayout 네트워크가 천장·바닥 경계를 예측하면, 바닥 경계를 가정된 카메라 높이로 역투영하여 방의 너비와 깊이를 산출한다. 천장 높이는 동일 방위각의 바닥과 천장이 같은 벽면 지점을 지시한다고 보고 바닥에서 구한 수평 거리에 맞춰 결정한다.

표면 텍스처는 두 경로로 구성된다. 1순위는 실사 정합이다. 경계선에서 벽–벽 코너가 정확히 두 개 검출되는 구도인 경우, 화각으로 구성한 내부 파라미터와 함께 RANSAC [20] 기반 PnP로 카메라 포즈를 산출하고, 평면 호모그래피로 벽·바닥·천장 다섯 면을 정면 시점으로 변환하여 실사 텍스처로 사용한다. 포즈 산출이 성공으로 보고되어도 평균 재투영 오차가 임계값을 초과하면 신뢰하지 않고 폴백으로 전환하며, 면 단위로 실제 촬영된 픽셀 비율이 낮은 면도 정밀 텍스처에서 제외한다. 이 두 검사를 적용하기 전에는 영상 가장자리를 코너로 오검출한 사진에서 왜곡된 텍스처가 적용되었다.

2순위는 사진 패치 타일링이다. 원본 영상에서 무늬가 균일한 100×100 패치를 선택하여 반복 적용한다. 단순히 분산이 가장 낮은 영역을 선택하면 그림자나 조명 그라데이션 영역이 선택되어 타일링 시 그림자가 반복된다. 본 시스템은 가우시안 블러로 저주파 조명 성분을 추정해 나누는 평탄화를 먼저 적용하고, 잔여 고주파 성분의 표준편차가 가장 낮은 패치를 선택한다. 채널값이 245 이상으로 포화된 영역은 후보에서 제외하고, 가구 제거에 사용한 SAM2 마스크를 재사용하여 가구가 있던 영역도 후보에서 제외한다. 이 마스크 재사용이 없을 경우 블라인드 그림자나 침대 하부와 같이 분산은 낮으나 벽이 아닌 영역이 선택되었다. 잔여 표준편차가 임계값보다 낮으면 무늬가 없는 면으로 판정하여 타일링 대신 평균색 단색으로 채운다.

방은 벽 두께 0.08 m, 바닥 두께 0.04 m, 걸레받이 0.10 m의 박스로 구성하며, 각 면에 비가시 충돌·레이캐스팅 평면을 배치하여 시각적 형상과 배치 좌표계를 일치시킨다.

### 가구 3D 복원

가구 크롭은 마스크 바운딩 박스로 분리한 뒤 긴 변 기준 512~1024 px로 정규화하고, 마스크 외부를 회색(128)으로 채워 SAM3D에 입력한다. 소형 물체를 512 px까지 확대하는 것은 깊이 추정 정확도를 위한 것이고, 대형 영상을 1024 px로 축소하는 것은 처리 속도를 위한 것이다.

SAM3D는 생성 모델이므로 동일 입력에 대해서도 난수 시드에 따라 결과가 크게 달라진다. 일부 시드는 정상적인 입체를 생성하고 일부 시드는 평면에 가까운 형상을 생성한다(그림 4). 사용자가 3D 변환을 요청할 때마다 결과 품질이 달라지면 서비스로 활용할 수 없다.

본 논문은 카테고리별 기하 기준에 의한 다중 시드 선택을 적용한다. 거친 복셀을 생성하는 1단계만 서로 다른 시드로 다섯 번 수행한 뒤 점수가 가장 높은 시드로 전체 파이프라인을 한 번 실행한다. 점수 기준은 카테고리에 따라 다르다. 일반 가구는 복셀의 세 축 범위 중 최솟값을 최대화한다. 가장 얇은 축이 두꺼울수록 입체적이라는 의미이다. 조명·꽃·화분과 같이 본래 얇은 물체에 이 기준을 적용하면 가장 부정확하게 복원된 결과가 선택되므로, 이들은 복셀 개수를 최대화하여 구조적 완전성을 우선한다.

이 방식의 비용은 처리 시간이다. 본 논문은 탐색 단계가 최종 메쉬를 생성하지 않는다는 점에 착안하여 추론 스텝을 축소하였다. 탐색은 시드의 순위만 결정하고 선택된 시드로 본 실행이 기본 스텝 수로 재수행되므로, 탐색 단계만 25스텝에서 10스텝으로 축소하였다. 다만 거친 복셀로 순위를 결정하게 되므로 선택되는 시드가 달라질 수 있다는 절충이 존재한다.

액자·거울·시계와 같이 얇은 물체는 SAM3D가 두께가 거의 없는 판으로 복원하여 3D 뷰의 측면에서 소실된다. 본 시스템은 두 단계로 대응한다. 먼저 카테고리에 따라 개략적인 형상 힌트를 포인트맵으로 생성하여 모델에 함께 입력한다. 액자·거울·시계는 가장자리가 후퇴하는 원반형 깊이를, 조명·꽃·화분은 하단이 더 가까운 원뿔형 깊이를 부여한다. 그럼에도 두께가 부족하면 후처리로 메쉬의 최소 축을 최대 축의 25 % 또는 최소 5 cm까지 중심 기준으로 확대한다.

**Fig. 4.** 시드 의존성. (a) 단일 시드로 3회 실행한 결과. (b) 1단계를 5회 탐색하여 카테고리 기준으로 선택한 결과.

색상 재현 방식으로는 UV 텍스처 베이킹과 버텍스 컬러를 비교하였다. UV 베이킹은 메쉬 추출 이후 다시점 렌더링으로 색상을 UV 공간에 투영하는 후처리 방식이고, 버텍스 컬러는 SAM3D의 학습된 메쉬 디코더가 색상을 직접 회귀하여 출력하는 값이다. 본 시스템은 두 가지 이유로 버텍스 컬러를 채택하였다. 첫째, UV 베이킹은 처리 시간이 복셀 수뿐 아니라 UV 아일랜드 수에 크게 좌우되어 예측이 불가능하다. 둘째, 단일 영상 조건에서는 미관측 면의 실제 색상 정보가 존재하지 않으므로, 다수의 가상 시점을 평균하는 베이킹은 UV 아일랜드 경계를 넘는 색상 번짐을 발생시킨다. 반면 버텍스 색상은 좌표 기반 sparse latent 공간에서 신경망이 직접 추론하므로 시점 간 불일치가 발생하지 않는다.

출력 단계에서는 3D 뷰어 조명 환경에서의 색상 재현을 위해 밝기를 1.15배, 감마를 0.85로 보정한다. 면 수가 80,000을 초과하면 쿼드릭 오차 기반 간략화 [21]를 적용하고, 색상은 원본 버텍스에 대한 KD 트리 최근접 질의로 이전한다.

### 가구 크기 추정

SAM3D가 생성하는 메쉬는 정규화 좌표계에 있다. 형상은 정확하지만 해당 객체가 몇 미터인지는 메쉬 자체에 포함되지 않는다. 반면 방은 미터 단위로 구성되어 있으므로, 스케일을 잘못 산정하면 침대가 방보다 커지거나 옷장이 축소 모형 크기가 된다. 본 논문은 네 단계 폴백 체인을 설계하였으며, 각 단계는 이전 단계가 성립하지 않는 조건에서만 호출된다(그림 5).

**경로 1: 카메라 포즈 기반 광선–바닥평면 교차.** 바닥에 접촉하는 가구는 원근을 역이용할 수 있다. 카메라 포즈가 주어졌을 때 가구 바운딩 박스의 하단 중앙 픽셀을 바닥 접촉점으로 간주한다. 카메라에서 해당 픽셀 방향으로 광선을 투사하여 방 좌표계의 바닥 평면과 만나는 지점을 구하면 카메라로부터 해당 가구까지의 거리를 알 수 있다. 카메라 위치는 회전 행렬과 이동 벡터로부터 얻고, 광선 방향은 픽셀 좌표를 내부 파라미터로 정규화한 뒤 방 좌표계로 회전시킨다. 바닥과의 교차 매개변수는 카메라 높이를 광선 방향의 Y 성분으로 나눈 값의 음수로 결정되며, 교차점을 카메라 좌표계로 변환하여 광축 방향 깊이를 얻는다. 이후 핀홀 카메라 모델 [22]의 비례 관계에 의해 실제 높이는 픽셀 높이에 깊이를 곱하고 수직 초점거리로 나눈 값으로 산출된다. 핵심은 원근 보정이다. 영상에서 동일한 픽셀 높이로 관측되어도 멀리 있는 가구가 실제로는 더 크므로, 거리를 직접 계산에 반영하여 이 오차를 제거한다.

이 방법의 전제는 두 가지이며 그것이 곧 한계이다. 하나는 가구가 바닥에 접촉하고 그 접점이 영상에 보인다는 것이다. 다른 하나는 카메라 포즈가 존재해야 한다는 것인데, 현행 구현에서 포즈는 실사 정합이 모두 성공한 경우에만 생성된다. 벽–벽 코너가 정확히 두 개 검출되고, PnP가 수렴하며, 평균 재투영 오차가 임계값 이하여야 한다. 세 조건 중 하나라도 성립하지 않으면 사이드카는 포즈를 반환하지 않고 체인은 경로 1을 건너뛴다.

**경로 2: Cube R-CNN 기반 크기 추정.** 액자·거울·벽걸이 조명·커튼은 공중에 위치한다. 바운딩 박스의 하단이 바닥이 아닌 벽면을 지시하므로 경로 1을 적용하면 광선이 더 먼 바닥과 교차하여 크기가 과대추정된다. 본 시스템은 이 카테고리를 별도 목록으로 관리하여 경로 1을 시도하지 않고, Cube R-CNN [16] 실내 체크포인트를 사이드카로 사용한다. 이미 SAM2로 정확한 2D 박스를 알고 있으므로 검출 단계를 생략하고 박스와 클래스를 oracle 2D로 주입하여 크기 예측만 수행한다. 한국어 카테고리는 실내 체크포인트의 영어 라벨로 매핑하며, 매핑이 존재하지 않는 카테고리는 사이드카가 즉시 미지원으로 응답한다. 실내 체크포인트의 분류 체계에는 시계·화분·꽃이 포함되지 않으므로, 본 시스템은 지원 목록을 코드에 명시하고 미지원 카테고리를 다음 경로로 이동시킨다.

**경로 3과 4.** 경로 1과 2가 모두 성립하지 않으면 SAM3D 포즈 디코더가 출력하는 인스턴스 스케일 값을 사용한다. 이 값은 정규 좌표계를 실제 크기로 환산하는 등방 배율이므로 메쉬의 정규 좌표 범위에 곱하면 미터 단위 크기가 된다. 최종 폴백은 방 너비의 0.2배로, 정보가 없는 경우에도 비현실적인 크기가 출력되지 않도록 하는 안전장치이다.

현행 구현의 단서를 덧붙이면, 뷰어는 가구 이름이 표준 치수 테이블에 매칭되는 경우 체인의 추정값 대신 표준 치수로 스케일을 적용한다. 즉 위의 네 경로는 표준 테이블에 매칭되지 않는 가구에서 작동한다. 이 설계는 일반적인 가구에서 결과를 안정화하는 대신 서로 다른 두 근거가 공존하게 하며, 본 논문은 이를 정리되지 않은 지점으로 기술한다. 또한 어떤 경로가 선택되었는지는 배치 시마다 로그로 기록한다.

### 인터랙티브 배치

복원된 메쉬는 Three.js 씬에서 드래그 앤 드롭으로 배치된다(그림 6). 3D 원근 뷰와 2D 조감도를 전환할 수 있고, 이동·90° 회전·크기 조절·복사·삭제가 가능하며, 작업 이력은 스냅샷 방식으로 되돌릴 수 있다. 완성된 디자인은 메쉬 데이터 크기로 인해 로컬 스토리지 대신 IndexedDB에 저장한다.

충돌 처리는 물리 엔진 대신 축 정렬 바운딩 박스(AABB) 검사 [23]와 위치 롤백으로 구현하였다. 초기 버전은 물리 엔진을 사용하였으나 인테리어 배치에서는 가구가 이동 후 정지해야 하므로, 단순 검사와 롤백이 상호작용에 더 적합하였다. 드래그 중 매 이동마다 이동 전 좌표를 저장하고, 배치된 모든 바닥 가구와 X·Z 평면 및 Y 높이 범위의 교차를 동시에 검사하여 세 축이 모두 겹칠 때만 충돌로 판정한다. 충돌 시 이동 전 좌표로 복원하며, 0.04 m의 여유를 두어 벽면 밀착 배치가 가능하도록 하였다.

구현상 주의할 점은 Three.js의 자동 바운딩 박스 계산이 렌더 루프 이전에는 월드 행렬을 갱신하지 않아 부정확한 좌표를 반환한다는 것이다. 본 시스템은 각 객체의 축별 반경을 별도로 저장하고 그 값과 그룹 위치로 AABB를 직접 산출한다.

가구 위 적재 시나리오도 지원한다. 드래그 중 레이캐스트가 다른 가구의 상단 면, 즉 법선의 Y 성분이 0.5 이상인 면에 교차하면 해당 높이에 아이템 반높이를 더해 자동으로 적재하고 충돌로 처리하지 않는다. 창문·액자 등 벽 부착 카테고리는 벽 평면 위에서만 이동하고, 천장 조명은 천장 평면을 따라 이동하며, 두 부류 모두 바닥 충돌 검사에서 제외된다.

렌더링 부하 역시 고려하였다. 초기에는 조작이 없어도 매 프레임 전체 씬을 재렌더링하였으나, 현재는 씬을 변경한 측이 무효화를 호출한 뒤 300 ms 동안만 렌더링한다. 단일 프레임이 아닌 300 ms의 여유를 둔 것은 지오메트리 추가나 텍스처 디코딩이 다음 프레임에 걸쳐 반영되는 경우를 누락하지 않기 위함이다. 사이드바의 가구 썸네일도 각각 독립된 3D 씬이므로 화면 밖으로 이동하거나 탭이 비활성화되면 렌더링을 중단한다.

## EXPERIMENTS AND RESULTS

### 실험 환경

시스템은 NVIDIA GeForce RTX 4090(24 GB), CUDA 12.1, PyTorch 2.5.1, Python 3.11 환경에서 동작한다. 백엔드는 FastAPI, 프론트엔드는 React와 Three.js로 구현하였으며, 영상 처리에는 OpenCV [24]를 사용하였다. 네 개의 프로세스는 단일 워크스테이션에서 함께 구동된다.

### 분할 성능

파이프라인의 첫 단계인 SAM2 분할은 정량 평가 스크립트로 측정하였다. 침대·의자·책상 각 4장, 총 12장의 실내 영상에 대해 LabelMe [25]로 정답 폴리곤을 직접 라벨링하고 두 지표를 계산하였다. 커버리지는 정답 영역 중 분할이 포함한 비율이고, 정밀도는 분할 영역 중 실제 가구인 비율이다. 임계값 0.8로 성공 여부를 판정하였다(표 1).

세 카테고리 모두 성공률 100 %에 커버리지 평균 85~100 %를 기록하였다. 정밀도는 의자 16.0 %, 책상 35.8 %, 침대 65.6 %로 낮은데, 이는 지표의 성격과 마스크 팽창이 함께 작용한 결과이다. 평가 스크립트는 인페인팅용 마스크 생성 경로를 호출하며, 이 경로는 가구 누락을 방지하기 위해 마스크를 의도적으로 확대한다. 가구 일부를 누락하면 해당 영역이 빈 방에 잔존하는 반면, 배경을 추가로 제거하는 것은 인페인팅이 복원한다. 따라서 이 수치는 분할 경계의 정밀함이 아니라 가구 누락 여부를 측정하는 값으로 해석해야 한다. 의자와 같이 얇은 다리와 등받이 격자 사이로 배경이 포함되는 형상에서 정밀도 저하가 가장 크게 나타났다.

다만 평가 스크립트는 현행 백엔드가 아니라 초기 버전의 분할 서비스를 참조하며, 해당 버전은 팽창 커널이 현행(15 px, 1회)보다 크다(40×40, 2회). 따라서 표 1의 커버리지는 현행 시스템에 대한 보수적 하한으로 볼 수 있으나 정밀도 수치는 현행 파이프라인의 값이 아니며, 현행 경로에서의 재측정이 필요하다.

### 가구 높이 추정 정확도

경로 1이 전제 위에서 어느 정도의 정확도를 갖는지 확인하기 위해 실제 방에서 줄자로 측정한 높이와 추정값을 비교하였다(표 2). 전제가 성립하는 정상 조건에서는 의자 1.06 m에 대해 1.057 m, 책상 0.74 m에 대해 0.700 m가 산출되어 오차가 각각 0.3 %와 5.4 %였다. 가구를 방 내부에 배치하는 용도로는 충분한 정확도이다. 실험 영상은 촬영자가 선 상태에서 약 1.57 m 높이에서 촬영한 것으로, 시스템이 가정하는 1.6 m와 2 % 이내로 일치한다. 후술하듯 본 파이프라인의 절대 스케일은 가정된 카메라 높이에 선형 비례하므로, 이 조건에서는 가정값이 기여하는 오차가 2 % 이내로 작다.

전제가 성립하지 않는 두 조건에서는 오차의 방향까지 예측과 일치하였다. 가구가 화면을 가득 채우는 클로즈업 촬영에서는 0.9 m 의자를 1.385 m로 54 % 과대추정하였다. 이 구도에서는 방 경계가 거의 관측되지 않아 레이아웃과 카메라 포즈가 충분히 구속되지 않으며, 그 결과 광선–바닥 교차로 얻는 깊이가 실제보다 크게 산출된다. 반대로 가구 하단부가 가려진 경우에는 0.8 m 의자가 0.454 m로, 2.0 m 책장이 1.251 m로 각각 43 %와 37 % 과소추정되었다. 가려진 하단부로 인해 바운딩 박스의 하단이 바닥 접점이 아니라 가림이 시작되는 지점을 지시하므로 광선이 더 가까운 바닥과 교차하여 깊이가 축소되고, 동시에 픽셀 높이도 잘린 만큼 감소한다. 두 오차가 같은 방향으로 중첩되어 과소추정이 확대된다.

중요한 것은 오차의 크기가 아니라 성격이다. 전제가 성립하지 않을 때 이 방법은 실패를 보고하지 않고 그럴듯한 값을 출력한다. 벽걸이 카테고리를 목록으로 관리하여 경로 1을 시도하지 않도록 한 것이 이 성질에 대한 대응이며, 가림 여부를 자동 판정하여 동일한 방식으로 경로를 전환하는 것이 향후 과제이다. 한편 실제 사용자 영상은 뒷벽 정면 구도가 아닌 경우가 많아 경로 1이 이론상 1순위이면서도 실행 빈도에서는 1순위가 아닐 수 있는데, 경로별 발동 빈도는 아직 측정하지 않았다.

### 절대 스케일의 근거

경로 1을 구현한 뒤 확인한 사실은, 방 치수와 가구 높이가 모두 하나의 상수인 가정된 카메라 높이에 선형 비례한다는 점이다. uLayout이 바닥 경계를 역투영할 때 이 값이 곱해지고, PnP에 입력하는 3차원 점 자체가 그 치수로 구성되므로, 포즈를 정확히 산출하더라도 절대 스케일은 이 가정에 종속된다. 즉 이 상수는 포즈를 얻지 못했을 때 사용하는 대체값이 아니라 방 좌표계의 길이 단위이다. 현행 시스템은 이 값을 1.6 m로 고정하고 있다.

여기서 도출되는 결론은 두 가지이다. 첫째, 방과 가구의 비율은 보존된다. 두 값이 동일한 상수에 비례하므로 상수가 부정확해도 비율은 유지된다. 둘째, 절대 치수는 전체가 함께 부정확해진다. 이를 확인하기 위해 바닥에 접촉하는 가구들의 3D 박스 하단에서 카메라 높이를 역산하는 구성을 별도로 검증하였다(표 3). 추정 천장 높이는 3.35 m에서 2.27 m로, 역산된 카메라 높이는 1.083 m로 산출되었으며, 치수가 1.6/1.083 = 1.477배만큼 축소된 것을 확인하여 앞서의 선형 관계를 검증하였다. 국내 주거 천장고가 2.3 m 전후임을 고려하면 후자가 타당한 값이다.

이 결과는 표 2와 함께 해석해야 한다. 표 2의 영상은 약 1.57 m에서 촬영되어 가정값과 2 % 이내였고 오차가 0.3~5.4 %에 머물렀다. 반면 표 3의 영상은 역산된 촬영 높이가 1.083 m로, 동일한 파이프라인이 방과 가구를 함께 1.477배로 확대하였다. 두 실험을 함께 놓으면 결론이 분명해진다. 경로 1의 기하 자체는 정확하며, 그 정확도는 실제 촬영 높이가 가정값에 근접하는 정도에 종속된다. 다만 이 검증은 표본이 소수이고 역산 정확도가 Cube R-CNN의 추정에 의존하므로 현행 시스템에는 통합하지 않았다.

### 단일 GPU에서의 자원 경합

측정 과정에서 확인된 것은 처리 시간 자체보다 그 불안정성이었다. 백엔드와 두 사이드카가 하나의 GPU에 적재되면 여유 VRAM이 2.4 GB까지 감소하고, 이 상태에서 프로세스 간 GPU 작업이 중첩되자 SAM3D의 디코드 단계가 0.2초에서 67초로 증가하는 것을 실측하였다.

원인을 추적한 결과 Stable Diffusion과 ControlNet이 fp16으로 3~4 GB를 상시 점유하는 반면, 실제로는 세션당 한 번, 로드에 7.6초가 소요되는 모델이었다. 본 시스템은 이 모델을 서버 시작 시 로드하지 않고 인페인팅 요청에서 로드한 뒤 즉시 해제하도록 변경하였다. 로드에 실패하는 경우 LaMa 결과만으로 동작하므로 품질은 저하되나 기능은 유지된다.

동일한 맥락의 메모리 관리 문제도 확인하였다. SAM3D 파이프라인 로드가 예외 처리 외부에 있으면 로드 중 메모리 부족 발생 시 부분 할당된 텐서가 GPU에 잔류하고, 지역 변수가 파이프라인 객체를 참조하여 캐시 정리가 무효화된다. 실패 1회당 약 13.5 GB가 잔류하여 서버 재시작 전까지 복구되지 않았다. 현재는 로드를 예외 블록 내부로 이동하고 지역 참조를 명시적으로 해제하며, 시드 탐색 5회분의 중간 결과도 각 반복 직후 해제한다.

### 임계값 결정

텍스처 패치 판정에 사용하는 두 상수는 실측으로 결정하였다. 꽃무늬 벽지의 원본 표준편차는 약 26.65, 그라데이션만 존재하는 무지 벽은 약 13.57로 측정되어 그 사이값인 18.0을 임계값으로 설정하였다. 평탄화 커널 크기도 동일한 방식으로 결정하였다. 초기에는 영역 크기의 비율로 커널을 설정하였으나, 이 경우 꽃무늬 벽지의 잔여 표준편차가 17.3까지 감소하여 임계값 아래로 잘못 내려갔다. 평탄화가 벽지 무늬 자체를 조명 성분으로 오인하여 제거한 것이다. 100×100 패치 기준으로 커널 9 px에서는 16.98, 21 px에서는 20.96이 측정되었고 그라데이션 벽은 커널과 무관하게 12.7 부근으로 안정적이어서 21 px을 채택하였다. 표본이 소수이므로 일반화가 부족하며, 두 상수를 코드 상단에 분리하고 재조정이 필요함을 명시하였다.

## CONCLUSION

본 논문은 단일 실내 사진에서 사용자의 실제 가구를 3D로 복원하여 재배치하는 end-to-end 시스템을 제안하고, 구현 과정에서 마주친 문제와 그 대응을 보고하였다. 사용한 모델들은 각각 문서화되어 있으나, 실내 사진이라는 도메인과 단일 GPU라는 제약이 중첩되는 지점에서는 원 논문이 다루지 않은 설계 결정이 필요하였다. ControlNet 조건 맵의 마스크 내부 엣지 제거, 카테고리별 시드 선택 기준, 4단계 크기 추정 폴백, 사이드카 분리와 온디맨드 로딩이 이에 해당한다.

본 시스템의 한계는 다음과 같다. 첫째, 단일 영상의 근본적 한계로 소파 후면과 같은 미관측 면은 shape prior의 추정에 의존한다. 둘째, 가구 높이 추정이 촬영 구도에 민감하며, 클로즈업이나 하단부 가림이 존재하면 오차가 수십 퍼센트에 이르고 시스템이 이를 자체적으로 감지하지 못한다. 셋째, 절대 스케일이 가정된 카메라 높이 위에 구성되어 있어 실제 촬영 높이가 가정값에서 벗어난 비율만큼 방과 가구가 함께 부정확해진다. 넷째, 실사 텍스처 정합이 코너 두 개가 검출되는 뒷벽 정면 구도에서만 동작한다. 다섯째, 가구 하나의 3D 변환이 실시간이 아니며, 이를 고려하여 일괄 변환 대신 사용자가 요청한 가구를 비동기로 변환하도록 설계하였다. 여섯째, 텍스처 판정 임계값이 소수 표본에 기반하며 투명 재질이나 고세밀 격자 구조 가구에서 복원 품질이 저하된다. 일곱째, 정량 검증이 분할과 높이 추정에 한정되어 있으며, 3D 복원 품질과 배치 결과 전반에 대해서는 정답 메쉬가 없어 정성 비교에 머물렀다.

향후 과제로는 절대 스케일 확보가 가장 우선한다. 본 논문은 카메라 높이를 영상에서 역산하는 경로를 검증하고 그 방향이 유효함을 확인하였으나, 표본과 신뢰도가 통합을 정당화할 수준에 이르지 못하였다. 다음 단계는 단일 영상 기반 미터 단위 깊이 추정 모델로 카메라 높이를 교차 검증하여, 두 독립 경로가 동일한 값을 산출할 때에만 채택하는 구조를 구성하는 것이다. 또한 가림 여부를 자동으로 판정하여 경로를 전환하는 기능과 경로별 발동 빈도의 정량화가 필요하다.
